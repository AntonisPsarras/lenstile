# Release baseline diagnostics

The development baseline is available at `tests/baseline-runner.html` when the
repository is served with the documented Python static server. It is disabled
until the user presses **Run baseline**. The page installs the in-memory test
download adapter before registering its button handler; it never downloads,
persists, or writes generated files.

## Fixture provenance

`tests/fixtures/procedural-baseline-fixture.js` is project-authored source
distributed under this repository's MIT license. Its pixels are generated by
fixed integer formulas. It uses no third-party image, font, network resource,
random value, or time seed.

## Privacy boundary

The collector keeps at most 64 workflow records and 128 stage records. Its
allowlist accepts fixed case/profile/stage identifiers plus numeric timings,
sizes, and counters. It excludes filenames, design names, source pixels,
palettes, masks, mesh coordinates, complete user-agent strings, arbitrary
metadata, and error text.

`exactKnownBytes` contains byte lengths obtained from typed-array views,
`ArrayBuffer` objects, encoded XML, ZIP bytes, and `Blob.size`.
`logicalEstimates` is intentionally separate. Its values are payload estimates,
not measurements of heap use or peak memory. In particular, the UTF-16 value is
the XML string's code-unit count multiplied by two, and the known-live-buffer
value is only a lower-bound sum that may double-count buffers retained across
cases.

Timing uses `performance.now()` only at coarse operation boundaries. Timings do
not select branches, change algorithm input, determine correctness-test
pass/fail, or alter serialized output.

## Workflow matrix

The runner covers both `nozzle04` and `nozzle02`, four and eight image colors,
Flat and Relief surfaces, and STL plus multicolor 3MF. This is 16 export cases
from four processing configurations. A separate rapid-supersede probe queues
two worker requests and observes stale-work completion; it does not cancel work.

Long-task counts are reported only when the browser implements
`PerformanceObserver` entry type `longtask`. Queue/transfer delay is labeled as
an estimate and is calculated as non-negative main-thread round-trip duration
minus worker-reported execution duration.

## Artifact inventory

Milestone 1 inventories existing large artifacts without deleting, renaming, or
regenerating them. Review `hardware/` and intentional fixtures under `tests/`
before any later cleanup. Binary provenance or removal requires separate
approval; this milestone does not alter tracked STL, 3MF, image, or other
binary files.

## Measurement limits

Browser scheduling, CPU power state, garbage collection, and background work
make elapsed timings nondeterministic. The collector does not claim measured
heap or peak resident memory. Worker queue/transfer delay is derived, not
directly measured. Long-task observation is browser-dependent. Run comparisons
on the same browser and machine, preferably after a warm-up, and compare output
goldens separately from performance values.
